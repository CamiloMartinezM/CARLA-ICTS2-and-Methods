## Installation
### Install Carla 0.9.15
The code is based on CARLA 0.9.15. The installation instructions can be found here: https://carla.readthedocs.io/en/0.9.15/start_quickstart/.
After the installation you may need to install [C++ redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist) and [DirectX runtime](https://www.microsoft.com/de-de/download/details.aspx?id=35) .

### Setup python
To set up python, we recommend using anaconda, or some sort of virtual environment (e.g., [virtualenvwrapper](https://virtualenvwrapper.readthedocs.io/en/latest/))
Make sure to install python 3.10, as newer versions may break the code.
The required python packages can be installed with:

> `pip install -r requirements.txt`

The [Makefile](Makefile) has some useful commands to set up the environment with [virtualenvwrapper](https://virtualenvwrapper.readthedocs.io/en/latest/) and avoid problems with environment variables:
```
make create_environment
make requirements
```
## CARLA-ICTS2
The main file to export training data for the pedestrian path prediction is `main.py` and will be exported to the `P3VI/data` directory by default.
Running a scenario can be generated by running the following command:
> `python main.py`

This will run the scenarios specified in [run_config.yaml](run_config.yaml). There you can specify which scenarios to run, the quality of the CARLA server, the port to connect to, the cameras to use and save, the duration, fps, etc.

### Scenarios and Configurations
Unlike the [main](https://github.com/CamiloMartinezM/CARLA-ICTS2-and-Methods) branch, this repository contains a modification in the API of the scenarios, which allows to add new scenarios and configurations in separate classes. Namely, [carla_icts2/benchmark/scenarios/scenarios.py](carla_icts2/benchmark/scenarios/scenarios.py) contains the implementation of the scenarios, one class per scenario, inheriting from the `BaseScenario` class. Each scenario must implement its own `tick()`and `setup()` methods, which are called by the `World` class in the `benchmark/environment/world.py` file. The `tick()` method is called every frame and is responsible for updating the state of the scenario, while the `setup()` method is called when the scenario is initialized to set up the initial conditions. This way the [carla_icts2/benchmark/environment/world.py](carla_icts2/benchmark/environment/world.py) file is not bloaded with `setup_*()` methods for each scenario and its `tick()` method is not a giant `if-else` block to check which scenario is running.

Each scenario class is mapped to a string which is the name of the scenario to run in the [run_config.yaml](run_config.yaml) file:

```python
SCENARIO_MAP: dict[str, type[BaseScenario]] = {
    "01_int": Scenario01Int,
    "02_int": Scenario02Int,
    "03_int": Scenario03Int,
    "04_int": Scenario04Int,
    "05_int": Scenario05Int,
    "06_int": Scenario06Int,
    "07_int": Scenario07Int,
    # "01_non_int": Scenario01NonInt,
    # "02_non_int": Scenario02NonInt,
    # "03_non_int": Scenario03NonInt,
    # "04_non_int": Scenario04NonInt,
    # "05_non_int": Scenario05NonInt,
    # "06_non_int": Scenario06NonInt,
}
```
**Note:** The classes for the non-interactive scenarios are missing.

For completeness, this is the description for the [main](https://github.com/CamiloMartinezM/CARLA-ICTS2-and-Methods) branch:

> The implementation of the scenarios is found in the `benchmark/environment/world.py` file, within the `tick` method. In this method it is checked in which scenario the simulation is currently in and the respective controllers are called. Inside the `World` class there are also setup methods for each scenario, in which the controllers are initialized. In the setup methods all waypoints are generated and the decision boxes are set up. The setup methods are called inside the `restart` method of the `World` class which will also
initialize the spectator camera. The methods of the controllers are found in the `benchmark/environment/car_controller.py` and `ped_controller.py`.

> Within `benchmark/scenario.py` only the start and end, i.e. the goal for the vehicle to reach, are defined, as well as the initial positions of the actors and their assets. Scenarios `scenario01`-`scenario12` are the scenarios of **CARLA-CTS**, while `scenario01_int`-`scenario03_int` and `scenario01_non_int`-`scenario03_non_int` are the scenarios of **CARLA-ICTS**, modified for **CARLA-ICTS2**. The new scenarios of **CARLA-ICTS2** are `scenario04_int`-`scenario06_int` and `scenario04_non_int`-`scenario0_non_int`. **The new scenario added is `scenario07_int`**.

> The parameters are controlled inside the `config.py` in the root of the repository. These classes generate the different scene configurations for the scenarios. Here you can set all parameters of the scenarios, like their initial strategy of negotiation, and all distances the pedestrians walks. These need to be imported in the `benchmark/environment/environment.py` and then added the ´__init__´ method of the `GIDASBenchmark` class. Here `Config01`-`Config06` refer to the non-interactive scenarios of **CARLA-ICTS2**, and `IConfig01`-`IConfig06` refer to the interactive scenarios of **CARLA-ICTS2**. The **IConfig07** refers to the new interactive scenario added in this repository.

### Training/Testing
Visit the original [CARLA-ICTS2 repository](https://github.com/CarlaICTS2/CARLA-ICTS2-and-Methods) for training and testing instructions. The folders containing the necessary code for training and testing were deleted from this repository to keep it clean and focused on the new scenarios and configurations. Nevertheless, the folders are *plug and play* and can be added to this repository if needed.
